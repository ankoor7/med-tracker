# Agent doctrine ledger

Provenance and lifecycle for every rule in
[`.claude/agents/sequential-fix-orchestrator.md`](../.claude/agents/sequential-fix-orchestrator.md)
(spec: [`specs/agent/agent-stage-5-self-tuning-doctrine.md`](../specs/agent/agent-stage-5-self-tuning-doctrine.md),
FR-A5.1 – FR-A5.3).

**Why a ledger.** The doctrine is itself a long-running system, and it had the
failure mode of one: every incident added a rule, no rule was ever removed, and
each rule is context every future orchestrator pays for on every turn. So each
rule now carries the incident that bought it; each run classifies every rule
`fired`, `violated`, or `dormant`; and a rule dormant across three consecutive
runs is proposed for removal. The ledger keeps the text, so removal is one edit
to undo — that is what makes pruning cheap enough to actually try.

It lives here rather than inline because a provenance comment beside each rule
would be prompt-visible noise: the reader who needs the provenance is a human
auditing the doctrine, not the orchestrator executing it.

## How to use it

```
pnpm agent:doctrine check                 # AC-A5.1 coverage + AC-A5.3 no-silent-growth
pnpm agent:doctrine audit --run <id> --append   # FR-A5.2, at run end
pnpm agent:doctrine prune                 # FR-A5.3 removal proposals
pnpm agent:doctrine size --record         # a new Size log row
pnpm agent:doctrine rules                 # what the parser sees as a rule
```

`pnpm agent:test` runs `check` against this repo, so a doctrine edit that skips
the ledger fails the suite rather than being noticed a month later.

Conventions:

- **Rules are identified by `section :: anchor`**, derived from the doctrine's own
  structure — a `##` heading, a list item, or a paragraph opening in bold. The
  anchor is the bold lead-in or the first sentence. Reword a rule past its anchor
  and the check fails: restating its provenance is the intended cost.
- **Ids are permanent.** They are assigned once and never reused or renumbered, so
  an audit from three runs ago still names the same rule. The table is ordered as
  the doctrine reads, which is why ids are not in sequence.
- **`provenance`** is a dated incident, a spec requirement, a file, or a sha — or
  the literal `prior`, meaning an untested belief. Priors are not a lesser class of
  rule, but they are marked, because AC-A5.3 will not let a prior buy net growth.
- **`class`** — `safety-critical` rules (mutation proof, the duplicate-spawn control,
  one-unit-one-commit, honest reporting of pending work) are exempt from pruning.
- **`status`** — `active`, `proposed-removal` (still in the doctrine, dormancy
  proposal pending), or `pruned` (removed from the doctrine, text recoverable from
  git plus the audit that retired it).

### Standing proposals

- **D-02 (liveness check) — `proposed-removal`, superseded not dormant.** FR-A4.3
  replaces the remembered liveness exception with the outer loop's mechanical
  ceiling: a monitor that holds no context can watch continuously for free. The
  rule stays until A4's trial clears AC-A4.1/AC-A4.6, because A4's revert
  condition keeps the resident orchestrator available and the resident path needs
  it. Retire it in the same change that retires the resident path.
- **D-52 (verify each commit landed) — watch for dormancy.** The ratchet refuses
  the `committed` transition without a SHA git confirms
  (`assertCommitExists`), so this rule now instructs the orchestrator to do by
  hand what it cannot avoid doing. First rule to test the pruning loop on if two
  more audits read `dormant`.
